Técnicas de Aseguramiento de la Calidad

Las técnicas de aseguramiento de la calidad permiten verificar que el software cumpla con los requisitos establecidos y detectar errores durante las diferentes etapas de su desarrollo. Las pruebas de software son una de las principales actividades utilizadas para evaluar el funcionamiento de una aplicación y aumentar la confianza en su calidad.

Las pruebas pueden organizarse de acuerdo con diferentes criterios. Por un lado, los niveles de prueba determinan qué parte del sistema se está evaluando, desde componentes individuales hasta el sistema completo. Por otro lado, los tipos de prueba indican cómo se analiza el software, por ejemplo, observando su comportamiento externo o examinando su estructura interna.

En esta sección se presentan tres niveles principales: pruebas unitarias, pruebas de integración y pruebas de sistema. También se explican las pruebas de caja negra y caja blanca, que permiten evaluar el software desde diferentes perspectivas.

El objetivo es comprender qué analiza cada prueba, cuándo se utiliza y qué tipo de errores permite detectar.

Niveles de pruebas

Las pruebas unitarias verifican el funcionamiento de las partes más pequeñas del software, como una función, un método o una clase, de forma aislada.

Suelen ser realizadas por los propios desarrolladores mientras programan y pueden automatizarse para ejecutarse de manera rápida y repetida.

Permiten detectar errores en etapas tempranas, cuando corregirlos resulta más sencillo y económico.

Las pruebas de integración comprueban que distintos componentes, módulos o servicios funcionen correctamente cuando se combinan entre sí.

Buscan detectar fallas en las interfaces y en el intercambio de datos, por ejemplo, entre una aplicación y una base de datos o entre dos servicios.

Se realizan después de las pruebas unitarias, a medida que los componentes se van uniendo.

Las pruebas de sistema evalúan el software completo e integrado, en un entorno lo más parecido posible al real.

Verifican que se cumplan los requisitos funcionales y no funcionales, como el rendimiento o la seguridad, recorriendo los flujos completos de uso.

Suelen ser realizadas por un equipo de pruebas independiente del desarrollo.

Tipos de pruebas

Las pruebas de caja negra evalúan el comportamiento externo del software sin considerar cómo está construido por dentro.

Se diseñan a partir de los requisitos: se proporcionan entradas y se comprueba que las salidas obtenidas sean las esperadas.

Entre sus técnicas se encuentran la partición de equivalencia, el análisis de valores límite y las tablas de decisión.

Permiten detectar funciones faltantes o incorrectas, pero pueden dejar sin recorrer caminos internos del código.

Las pruebas de caja blanca analizan la estructura interna del software. En este tipo de prueba se conoce el código fuente y la lógica utilizada para construir el programa.

El análisis puede centrarse en las instrucciones, condiciones, estructuras y diferentes caminos de ejecución que puede seguir el programa.

Este enfoque permite comprobar que la lógica interna funciona correctamente y que las diferentes posibilidades de ejecución hayan sido evaluadas.
